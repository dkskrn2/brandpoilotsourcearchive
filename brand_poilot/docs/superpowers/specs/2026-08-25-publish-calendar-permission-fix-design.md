# 게시 캘린더 예약 권한 오류 수정 설계

## 문제

수동 게시 예약은 콘텐츠 생성 결과의 소속을 확인하기 위해 보호된 AI 콘텐츠 테이블을 조회한다. 현재 합성 저장소는 게시 캘린더 저장소를 일반 API DB 풀로 만들기 때문에, 운영 일반 역할이 `ai_content_generation_outputs`를 조회하는 시점에 권한 오류가 발생한다. API의 내부 오류는 UI의 기본 오류 문구 때문에 브랜드 불일치로 잘못 표시된다.

## 변경

- 게시 캘린더 저장소를 이미 분리되어 있는 `aiContentPool`로 생성한다.
- 일반 DB 역할에 AI 테이블 권한을 추가하지 않는다.
- 실제 테넌트 범위 오류만 브랜드 예약 불가 문구로 표시한다.
- 알 수 없는 서버 오류는 재시도를 안내하는 일반 예약 실패 문구로 표시한다.

## 비범위

- DB 스키마와 권한 변경
- 게시 큐, worker, 자동 배정 로직 변경
- 배포

## 검증

- 합성 저장소의 캘린더 조회가 일반 풀이 아닌 AI 콘텐츠 풀을 사용하는 단위 테스트
- 내부 오류와 테넌트 오류의 UI 문구가 구분되는 단위 테스트
- 기존 게시 캘린더 PostgreSQL application-role 통합 테스트
- API/UI 타입 검사와 관련 빌드
