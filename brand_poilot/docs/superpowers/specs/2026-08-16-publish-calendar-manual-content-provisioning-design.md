# 게시 캘린더 수동 콘텐츠 공급·일괄 주제 설계

작성일: 2026-08-16  
선행 설계: `2026-08-14-publish-calendar-operating-integration-design.md`

## 1. 문제

현재 게시 캘린더의 `수동 슬롯 추가`는 게시 시각과 콘텐츠 형식만 받아 콘텐츠가 없는 `open` 슬롯을 만든다. 이후 배정 UI도 이미 게시 그룹으로 준비된 일부 콘텐츠만 보여 주기 때문에 다음 요구를 충족하지 못한다.

- 생성 중인 콘텐츠를 미리 게시 슬롯에 연결할 수 없다.
- 생성은 끝났지만 게시되지 않은 결과물을 제대로 선택할 수 없다.
- 새 콘텐츠의 생성 1단계 정보를 캘린더 안에서 입력할 수 없다.
- 여러 주제와 게시 일정을 표로 일괄 등록할 수 없다.
- 콘텐츠 준비가 예약 시각보다 늦어진 경우의 자동 게시 정책이 없다.

최종 사용자 흐름에서 콘텐츠 없는 수동 슬롯을 만들지 않는다. 수동 슬롯 생성의 완료 단위는 `게시 일정 + 콘텐츠 공급 방식`이다.

## 2. 확정된 제품 결정

1. 수동 슬롯 추가 시 다음 중 하나를 반드시 선택한다.
   - 생성 중인 기존 콘텐츠
   - 생성 완료·미게시 기존 콘텐츠
   - 새 콘텐츠 만들기
   - 여러 새 주제 일괄 등록
2. 목적, 형식, 채널, 제품·서비스, 오늘의 주제 등 선택값은 프론트에 복제하지 않고 서버가 현재 브랜드 기준으로 제공한다.
3. 일괄 입력은 표 형태이며 목적·소재 방식·제품·형식·채널은 셀렉트박스를 사용한다.
4. 수동·일괄·자동 슬롯은 같은 브랜드와 채널 안에서 최소 30분 간격을 유지한다.
5. 콘텐츠가 예약 시각까지 준비되지 않아도 예약은 취소하지 않는다.
6. 늦게 준비된 콘텐츠는 사용자 재예약 없이 자동 게시한다.
7. 늦게 준비된 콘텐츠가 기존 예약과 충돌하면 기존 예약을 유지하고, 30분 이상 비는 가장 빠른 시각에 자동 재예약한다.
8. 슬롯 예약만으로 콘텐츠 생성 횟수를 차감하지 않는다. 실제 생성 시작 시 생성 한도를 사용한다.
9. 게시 예약 한도는 슬롯을 활성 예약하는 시점에 차지하며, 취소 시 반환한다. 게시 성공 횟수와 예약 점유량은 별도로 계산한다.

## 3. 사용자 경험

### 3.1 진입점

날짜를 선택하고 `게시 콘텐츠 추가`를 누르면 우측 상세 패널 위에 확장 모달 또는 드로어를 연다. 기존의 시간·형식만 있는 `수동 슬롯 추가` 폼은 제거한다.

첫 화면은 다음 네 가지 공급 방식을 보여 준다.

1. `생성 중 콘텐츠 선택`
2. `생성 완료·미게시 콘텐츠 선택`
3. `새 콘텐츠 만들기`
4. `여러 주제 일괄 등록`

### 3.2 생성 중 콘텐츠 선택

브랜드 소유의 비종료 generation을 조회한다. 목록에는 제목 또는 주제, 목적, 형식, 현재 단계, 생성 시작 시각을 표시한다.

- 슬롯은 generation ID에 연결된다.
- 생성 완료 callback이 정확한 output을 슬롯에 연결하고 기존 canonical publish preparation을 실행한다.
- 이미 다른 비취소 슬롯에 연결된 generation은 중복 배정할 수 없다.
- 슬롯 형식과 generation 형식이 다르면 선택할 수 없다.
- 실패·취소된 generation은 기본 후보에서 제외하고 실패 내역으로만 표시한다.

### 3.3 생성 완료·미게시 콘텐츠 선택

브랜드의 generation output 중 게시 완료되지 않았고 다른 활성 슬롯에 점유되지 않은 결과물을 조회한다.

- `pending_review` 결과는 선택할 수 있지만 슬롯은 `검토 필요`로 표시하고 승인 전 게시큐를 실행하지 않는다.
- `approved`, `auto_approved` 결과는 선택 후 canonical publish preparation으로 연결한다.
- `published`, `rejected`, terminal generation failure는 선택할 수 없다.
- 기존 topic publish group이 있는 경우 새 그룹을 만들지 않고 그 그룹을 연결한다.
- 후보 API는 `assignable`과 `blockedReason`을 제공해 UI와 서버 판정이 어긋나지 않게 한다.

### 3.4 새 콘텐츠 만들기

캘린더는 기존 생성 플로우를 복제하지 않고 1단계 입력을 수집한 뒤 기존 플로우에 slot context를 전달한다.

수집 항목:

- 게시 날짜와 시간
- 목적: 정보성 / 마케팅성
- 소재 방식: 직접 주제 / URL / 오늘의 주제 / 레퍼런스
- 직접 주제 또는 URL, 추천 주제 ID, 레퍼런스 ID
- 마케팅성인 경우 승인·활성 제품·서비스
- 콘텐츠 지시사항(선택)
- 형식: 현재 Instagram에서 생성·게시 가능한 카드뉴스 또는 릴스
- 채널: 현재 배포 범위에서는 연결·활성 Instagram

DB migration을 추가하지 않기 위해 Step-1 저장 시 슬롯을 먼저 만들지 않는다. 기존 콘텐츠 생성 플로우에서 구성안을 생성·선택해 generation draft ID를 얻은 뒤, 그 generation ID와 게시 슬롯을 한 transaction으로 생성·연결한다. 슬롯은 처음부터 `generation_pending`으로 표시한다. 구성안 선택, 레퍼런스/스타일/아바타 등 기존 생성 단계는 동일한 생성 화면을 그대로 사용한다.

generation draft가 만들어진 뒤에는 사용자가 생성 화면을 나가도 해당 draft가 생성 중 콘텐츠 후보에 남는다. 슬롯 배정 전에 이탈한 draft도 캘린더에서 다시 선택할 수 있다. 콘텐츠 없는 예약 슬롯은 만들지 않는다.

### 3.5 여러 주제 일괄 등록

일괄 등록은 새 콘텐츠 만들기의 1단계만 여러 행으로 입력하는 기능이다. 각 행은 하나의 콘텐츠 계획과 하나의 게시 슬롯이 된다.

| 열 | UI | 서버 기준 |
|---|---|---|
| 게시일 | 날짜 입력 | 미래 날짜 |
| 게시시간 | 시간 입력 | 기존 슬롯 포함 30분 간격 |
| 목적 | 셀렉트 | 서버 제공 목적 catalog |
| 소재 방식 | 셀렉트 | 서버 제공 subject mode catalog |
| 주제·URL·추천 | 방식별 입력 | 직접값 또는 브랜드의 활성 데이터 |
| 제품·서비스 | 검색 셀렉트 | 브랜드의 승인·활성 제품 |
| 형식 | 셀렉트 | 채널 capability와 게시 adapter가 모두 지원하는 형식 |
| 채널 | 셀렉트 | 연결·활성·게시 지원 채널 |
| 지시사항 | 텍스트 | 선택 입력 |

표 기능:

- 행 추가, 복제, 삭제
- 탭/화살표 키 이동
- 여러 줄 붙여넣기
- 목적·형식·채널·간격의 열 일괄 적용
- 카드뉴스/릴스 자동 혼합
- 첫 시각과 간격을 기준으로 날짜를 넘겨 자동 분산
- 기존 슬롯과 충돌하는 행을 셀 단위로 표시
- 제출 전 `기존 콘텐츠 N / 새 생성 N / 게시 슬롯 N` 한도 요약

각 행은 기존 구성안 생성·선택을 거쳐 generation draft ID를 먼저 얻는다. 모든 행의 generation ID가 준비된 뒤 하나의 brand advisory lock과 transaction으로 슬롯을 저장한다. 한 행이라도 슬롯 검증에 실패하면 어떤 슬롯도 저장하지 않고 행별 오류를 반환한다. 이미 만들어진 generation draft는 삭제하지 않고 생성 중 콘텐츠 후보로 남겨 재시도할 수 있게 한다. 기존 구성안 API의 idempotency key와 슬롯의 일정·lineage replay 검증으로 중복 생성을 막는다.

## 4. 선택값 공급 계약

프론트는 목적이나 형식을 자체 상수로 판단하지 않는다. 새 API가 현재 브랜드에서 실제 선택 가능한 값을 한 번에 제공한다.

`GET /brands/:brandId/publish-calendar/manual-options`

응답 범위:

- 목적 catalog와 표시명
- 소재 방식 catalog와 방식별 필수 입력
- 연결·활성 채널 및 지원 형식
- 승인·활성 제품·서비스
- 최신 활성 오늘의 주제
- 사용 가능한 레퍼런스
- 기본 콘텐츠 형식과 자동 혼합 정책
- 현재 주간 게시 예약 여유와 생성 사용 가능량

제품, 추천, 레퍼런스, 채널 연결 상태는 DB에서 브랜드 범위로 조회한다. 목적과 형식처럼 코드 계약으로 정의된 값도 서버가 capability와 adapter 상태를 적용한 최종 허용 목록만 반환한다. 따라서 DB에 존재하더라도 현재 게시할 수 없는 값은 선택지에 노출하지 않는다.

## 5. 원자적 수동 슬롯 공급 API

최종 고객 API는 콘텐츠 없는 슬롯 생성과 별도 배정을 요구하지 않는다.

### 단건

`POST /brands/:brandId/publish-calendar/manual-slots`

discriminated payload:

- `source.kind = existing_generation`
- `source.kind = existing_output`
- 새 콘텐츠도 기존 플로우가 만든 generation ID를 사용하므로 `source.kind = existing_generation`으로 공급한다.

공통 필드에는 scheduledFor, channel, format, idempotencyKey를 둔다. source별 generation ID 또는 generation output ID를 요구한다. 생성 1단계 입력은 기존 proposal API에만 전달하고 캘린더 API에 복제하지 않는다.

### 일괄

`POST /brands/:brandId/publish-calendar/manual-slots/batch`

- batch idempotency key
- 각 행의 client row ID
- 각 행의 scheduledFor와 기존 플로우가 만든 generation ID

서버 검증 순서:

1. workspace/brand actor scope
2. brand advisory lock
3. 활성 구독과 현재 플랜
4. 서버 제공 catalog에 포함된 선택값인지 확인
5. 콘텐츠·제품·추천·레퍼런스 소유권
6. channel 연결·활성·adapter 지원
7. format과 channel delivery 형식 일치
8. 중복 콘텐츠 배정
9. 주간 게시 예약 한도
10. 새 생성 행의 생성 가능량
11. 미래 시각과 모든 활성 슬롯 사이의 30분 간격
12. slot + 기존 generation/output lineage를 원자 저장

기존 repository의 `createSlot`은 자동 allocator와 내부 orchestration에서 재사용할 수 있지만, 고객 UI는 콘텐츠 없는 슬롯을 완료 상태로 만들 수 없다. 현재 배포 UI와의 전환 기간이 끝난 뒤 기존 empty-slot 고객 route는 제거한다.

## 6. 상태와 게시 관리

상태 흐름:

```text
새 입력 → proposal_assigned → generation_pending
생성 완료 → content_assigned → ready → scheduled
예약 시각 도래 → publishing → published
예약 시각 초과·미준비 → publish_delayed
지연 콘텐츠 준비 → earliest-safe-time 계산 → scheduled → published
사용자 취소 → cancelled
```

UI 표시명:

- 생성 준비
- 생성 중
- 검토 필요
- 게시 준비 완료
- 예약 완료
- 게시 지연
- 게시 중
- 게시 완료
- 게시 실패
- 취소

슬롯 상세에는 slot의 원래 예약 시각과 연결된 publish queue의 실제 `scheduled_for`/`published_at`을 분리해 보여 준다. 새 DB 컬럼은 추가하지 않는다. 지연 게시에는 `기존 예약 보호를 위해 HH:mm에 자동 게시됩니다`를 표시한다.

## 7. 늦은 콘텐츠 자동 게시

예약 시각이 지났는데 콘텐츠가 준비되지 않으면 슬롯을 삭제하거나 실패 처리하지 않고 `publish_delayed`로 유지한다.

콘텐츠가 준비되는 순간 서버는 같은 브랜드·채널의 다음 항목을 확인해 earliest-safe-time을 계산한다.

1. 후보 시작 시각은 현재 시각이다.
2. 최근 실제 게시 시각과 30분 이내이면 30분 이후로 이동한다.
3. 활성 예약 슬롯의 예정 시각 전후 30분을 차단 구간으로 본다.
4. 첫 번째 빈 시각을 찾을 때까지 후보를 이동한다.
5. 기존 예약은 변경하지 않는다.
6. slot의 원래 예약 시각은 유지하고 계산 결과를 publish queue의 `scheduled_for`에 원자 반영한다.
7. 동일 callback 재실행은 같은 결과를 반환하고 queue를 중복 생성하지 않는다.

예: 지연 콘텐츠가 09:50에 준비되고 기존 예약이 10:00이면 기존 예약은 10:00에 게시하고 지연 콘텐츠는 10:30 이후 첫 빈 시각에 게시한다.

## 8. 한도 정책

- 활성 슬롯은 주간 게시 예약 여유를 차지한다.
- 게시 성공은 같은 reservation unit의 성공 전이이므로 이중 차감하지 않는다.
- 기존 콘텐츠 연결은 생성 한도를 사용하지 않는다.
- 기존 구성안 선택으로 generation draft를 만드는 것만으로는 생성 한도를 사용하지 않는다.
- 실제 generation 시작 시 기존 canonical generation gate가 한도를 차감한다.
- 일괄 저장 시 새 생성량이 현재 허용량을 넘으면 전체 등록을 막고 초과 행을 표시한다.
- 슬롯 취소는 게시 예약 여유를 반환한다.
- 이미 시작되거나 완료된 생성 사용량은 슬롯 취소로 반환하지 않는다.
- 지연 재예약은 같은 슬롯을 이동하는 것이므로 추가 게시 예약을 소비하지 않는다.

## 9. 수정과 취소

- 생성 시작 전: 주제, 목적, 소재, 제품, 형식, 게시 시각 변경 가능
- 생성 시작 후: 주제·형식 변경은 기존 generation을 덮지 않고 새 generation 흐름으로 처리
- publishing/published: 콘텐츠와 시각 변경 불가
- 슬롯 취소: 연결된 미실행 calendar queue도 같은 transaction에서 취소
- 기존 콘텐츠 교체: 실행 전이며 새 콘텐츠가 다른 활성 슬롯에 점유되지 않은 경우에만 허용
- 시간 변경: 서버에서 현재 시각·한도·30분 간격을 다시 검증

## 10. 오류와 복구

- catalog 일부 조회 실패 시 writable 기본값을 만들지 않고 해당 공급 방식만 비활성화한다.
- 단건·일괄 mutation 실패 시 기존 캘린더 데이터를 유지한다.
- generation 완료 후 publish preparation 실패는 generation 완료를 롤백하지 않고 슬롯을 `publish_delayed`로 남긴다.
- provider 게시 실패는 기존 제한된 retry 정책을 사용한다.
- 영구 오류는 무한 재시도하지 않고 상세에서 원인과 필요한 사용자 조치를 표시한다.
- 지연 자동 게시 scheduler가 잠시 중단돼도 다음 실행에서 overdue slot을 catch-up한다.

## 11. 영향 범위와 비영향 범위

영향 범위:

- 게시 캘린더 수동 등록 UI와 상세
- 콘텐츠 생성 1단계의 slot context
- calendar repository/API/DTO
- generation 완료 후 slot linkage
- 게시 준비와 지연 재예약
- 주간 게시 예약 및 생성 한도 표시

비영향 범위:

- Instagram DM
- FAQ, crawl, wiki
- 게시 캘린더와 무관한 worker
- 기존 직접 게시의 사용자 흐름
- 게시 결과 다운로드와 조회

테스트도 영향 범위만 실행한다.

## 12. 완료 조건

- 콘텐츠 출처 없이 수동 슬롯을 만들 수 없다.
- 생성 중, 생성 완료·미게시, 새 콘텐츠를 모두 슬롯에 연결할 수 있다.
- 일괄 표의 모든 선택형 값이 서버의 현재 브랜드 허용 목록에서 온다.
- 단건과 일괄 등록이 소유권·형식·채널·한도·30분 간격을 transaction 안에서 검증한다.
- 예약 시각보다 늦게 준비된 콘텐츠가 기존 예약을 보존하면서 가장 빠른 안전 시각에 자동 게시된다.
- 생성과 게시 사용량이 이중 차감되지 않는다.
- 기존 직접 게시와 게시 결과 경로가 회귀하지 않는다.
- 배포 전 영향 테스트, API/UI build, 실제 브라우저 QA가 통과한다.
- 다른 진행 중인 배포가 끝나고 운영 SHA/digest를 다시 확인하기 전에는 배포하지 않는다.
- 현재 배포 중인 DB migration 081과 충돌할 새 migration이나 schema 변경을 추가하지 않는다.
