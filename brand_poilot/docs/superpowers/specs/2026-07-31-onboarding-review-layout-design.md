# 온보딩 분석 검토 화면 정리

## 목표

온보딩 Step 2 검토 화면에서 회사명 입력을 분석 결과의 일부로 자연스럽게 배치하고, 사용자에게 불필요한 근거 상세 영역은 노출하지 않는다.

## 확정 UI

- `AI 분석 결과를 확인하고 수정하세요` 아래의 `분석 결과 확인` 패널 첫 필드에 회사명을 배치한다.
- 회사명은 다른 검토 항목과 동일한 `field-stack`, `field-label`, 기본 입력 스타일과 전체 너비를 사용한다.
- 현재 회사명만 들어 있는 별도 카드는 제거한다.
- `근거와 추가 확인 항목` 패널은 화면에서 제거한다.
- 경쟁사별 `근거 보기` 링크는 경쟁사 항목의 일부이므로 유지한다.
- 분석 결과의 `evidence`와 `sourceGaps` 데이터는 삭제하거나 변경하지 않고 확정 요청에 그대로 포함한다.
- 저장 오류와 `확인하고 저장` 버튼은 숨겨지는 근거 패널 밖의 별도 작업 영역으로 이동해 계속 노출한다.

## 구현 경계

`BrandAnalysisReviewStep`에 회사명 값과 변경 콜백을 전달한다. 이 컴포넌트가 회사명 필드와 저장 작업 영역까지 렌더링하도록 하여 검토 폼의 시각 구조를 한곳에서 관리한다. API, 분석 결과 계약, 확정 요청 형식은 변경하지 않는다.

## 고려한 대안

1. **검토 컴포넌트 첫 필드로 통합 — 채택.** 아래 항목과 동일한 디자인을 재사용하며 별도 카드가 사라진다.
2. 페이지 컴포넌트에 회사명 필드를 남기고 CSS만 맞추기. 구조적으로 별도 블록이 남아 간격과 반응형 동작이 다시 달라질 수 있어 제외한다.
3. 회사명을 분석 결과 JSON에 추가하기. UI 배치만을 위해 데이터 계약을 바꾸는 과도한 변경이라 제외한다.

## 검증

- 회사명 입력이 `분석 결과 확인` 패널 내부 첫 번째 편집 필드인지 확인한다.
- 회사명을 수정한 뒤 확정하면 수정값이 기존 확정 API 인자로 전달되는지 확인한다.
- `근거와 추가 확인 항목` 제목, evidence claim, source gap 문구가 렌더링되지 않는지 확인한다.
- 경쟁사 `근거 보기`, 저장 오류, `확인하고 저장`은 계속 렌더링되는지 확인한다.
- 고객 UI 관련 테스트와 프로덕션 빌드를 실행한다.
