# 카드뉴스·릴스 최종 문구 잠금 설계

## 목표

수동 V3 카드뉴스와 릴스의 최종 이미지 CLI가 기획 단계에서 확정된 `currentAsset.copy`를 다시 쓰지 못하게 한다. 원문, 선택 구성안, 전체 outline, 브랜드 정보와 모든 첨부를 읽는 현재 구조는 유지하되, 이 입력들은 사실·맥락·시각 참고에만 사용한다.

## 문제

현재 카드뉴스와 릴스 최종 이미지 프롬프트는 이미지 CLI에게 원문과 선택 구성안을 바탕으로 한국어 문구를 직접 작성하고, 긴 문장을 자연스럽게 압축하라고 지시한다. 이 지시는 `content-plan.json`의 장면별 `copy`와 충돌한다. 실제 운영 결과에서 기획된 근거 확인 문구가 일반적인 게시 전 체크리스트로 교체되었다.

## 결정

1. `inputs/content-plan.json`의 `imagePackage.assets`에서 `index`가 `inputs/render-contract.json`의 `assetIndex`와 같은 항목을 현재 자산으로 식별한다.
2. 현재 자산의 `copy`를 최종 확정 원고이자 모델이 새로 그릴 수 있는 유일한 편집 문구로 취급한다.
3. 카드뉴스와 릴스 이미지 CLI는 `copy`의 글자, 숫자, 문장부호, 공백, 줄바꿈과 순서를 추가·삭제·교체·요약·반복하지 않는다.
4. `visualDirection`, 원문, 선택 구성안, 전체 outline, 사용자 이미지 지시와 첨부 이미지에 포함된 문구는 새 편집 문구의 출처가 될 수 없다.
5. 모델은 확정 원고의 크기, 폰트, 색상, 위치, 대비와 주변 비문자 시각 요소만 설계한다.
6. 실제 선택 제품 사진 또는 포장에 이미 인쇄된 표시는 기존 공통 로고 정책에 따라 유지할 수 있다. 모델이 그 문구를 추출해 별도 편집 문구로 다시 쓰는 것은 금지한다.

## 변경 범위

- 카드뉴스 V2 최종 이미지 프롬프트
- 릴스 V2 최종 이미지 프롬프트
- 두 형식이 공유하는 소셜 문구 잠금 지시 빌더
- 해당 프롬프트 회귀 테스트

## 변경하지 않는 범위

- 구성안 CLI와 카드뉴스·릴스 기획 CLI
- 블로그 작성·HTML·보조 이미지 프롬프트
- 레거시 V1 이미지 프롬프트와 렌더 경로
- API, UI, DB, 저장 계약, 작업 계약과 `rendererPromptVersion`
- URL 수집, 동결 입력, 전체 outline, 근거와 첨부 전달 방식
- gpt-image-2 호출, 결과 JSON과 PNG 계약
- 서버 텍스트 합성 또는 OCR 재시도 추가

## 입력 권한 순서

1. `currentAsset.copy`: 최종 표시 문구
2. `currentAsset.visualDirection`: 정보 위계와 구도
3. 현재 role과 전체 outline: 장면 맥락
4. 고정 URL 원문·근거·브랜드 정보: 사실 확인
5. 첨부 이미지: 선택적 시각 참고

낮은 순위의 입력은 높은 순위의 문구를 변경할 수 없다.

## 호환성 판단

이번 변경은 현재 수동 V3 최종 이미지 프롬프트의 잘못된 책임만 교정한다. 저장 payload와 계약 버전은 바뀌지 않는다. 이미 queued 상태인 동일 V2 작업도 새 이미지 워커가 claim하면 잠긴 문구 정책을 적용받는다. 완료된 결과와 manifest 읽기 경로에는 영향이 없다.

## 오류와 한계

- 이 변경은 이미지 CLI가 내용을 재작성하는 것을 금지한다.
- gpt-image-2가 한글 글리프를 잘못 그리는 문제를 기술적으로 완전히 보장하지는 않는다.
- 정확한 글리프 보장이 필요하면 별도 OCR 검증 또는 결정론적 텍스트 렌더링 설계가 필요하지만 이번 범위에는 포함하지 않는다.

## 검증 기준

1. 카드뉴스와 릴스 프롬프트가 현재 index의 `copy`를 최종 확정 원고로 명시한다.
2. 두 프롬프트에서 문구 직접 작성과 자연스러운 압축 지시가 사라진다.
3. 계획에 없는 제목, CTA, 번호, 영문 라벨과 첨부 이미지 문구 추가를 금지한다.
4. `visualDirection`과 사용자 이미지 지시가 문구 권한을 갖지 못한다.
5. 카드뉴스·릴스의 기존 비율, 완성 픽셀, 사실 제한, 첨부 확인, 네트워크 금지와 결과 JSON 지시는 유지된다.
6. 블로그 및 V1 프롬프트 소스에는 diff가 없어야 한다.
7. 이미지 워커의 집중 테스트와 TypeScript 빌드가 통과해야 한다.
