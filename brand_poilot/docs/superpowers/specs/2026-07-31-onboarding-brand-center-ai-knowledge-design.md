# 온보딩·브랜드센터 AI 자동응답 지식 연결 설계

## 목표

온보딩에서는 사용자에게 URL과 문서만 받고, 분석 결과에서 회사명·브랜드 코어·대표 제품·서비스·FAQ를 제안한다. 사용자가 확정하거나 수정한 정보만 브랜드센터와 Instagram DM 자동응답의 공통 지식으로 사용한다.

## 확정된 화면 구조

브랜드센터 탭은 다음 순서로 고정한다.

1. 브랜드 코어
2. 제품·서비스
3. FAQ
4. AI 자동응답 지식
5. 스타일

`이용 방법` 탭은 제거한다. 기존 `가이드` 탭은 이름만 바꾸는 것이 아니라, 수동 등록형 화면 대신 실제 자동응답에 투입되는 지식을 확인하는 읽기 전용 화면으로 교체한다.

## 온보딩 입력과 회사명

- 자료 등록 단계에서는 회사명 입력을 제거한다.
- 사용자는 HTTPS 자사 URL 또는 지원 문서 중 하나 이상만 제공한다.
- 워커는 자사 URL과 첨부 문서에서 근거가 확인되는 회사명을 `companyNameSuggestion`으로 제안한다.
- 카카오 프로필 이름과 `brands.name`의 내부 임시값은 회사명 추출 근거로 사용하지 않는다.
- 회사명을 찾지 못하면 결과 확인 화면의 회사명 필드를 비워 둔다.
- 회사명은 결과 확인 화면의 첫 번째 필드에서 사용자가 수정할 수 있다.
- 최종 확인 시 회사명이 1~100자 규칙을 통과해야 하며, 그때만 `brands.name`과 `company_name_confirmed_at`을 갱신한다.

회사명 제안은 확정값이 아니므로 분석 결과 계약에서 별도 필드로 유지한다. 최종 저장 API는 지금처럼 사용자가 확인한 `companyName`을 받는다.

## 워커 결과 확장

기존 `brand-intelligence-result.v2`의 브랜드 코어와 대표 상품·서비스 구조는 유지하면서 다음을 추가한다.

```ts
type CompanyNameSuggestion = {
  name: string;
  sourceFactIds: string[];
} | null;

type FaqSuggestion = {
  question: string;
  answer: string;
  category: "service" | "product" | "price" | "location" | "operation" | "other";
  sourceFactIds: string[];
};
```

- 회사명과 FAQ는 검증된 자사 사실만 사용한다.
- FAQ 질문·답변마다 기존 `sourceFactIds`를 유지한다.
- FAQ는 서비스 문의, 제품 문의, 가격, 위치, 운영 안내를 우선하고 근거가 없는 항목은 만들지 않는다.
- 기존 대표 상품·서비스 추출 단계에서 회사명과 FAQ도 함께 추출해 CLI 호출 수를 늘리지 않는다.
- 최종 감사 단계는 등록되지 않은 fact ID가 포함된 회사명·FAQ를 제거한다.

## 대표 제품·서비스 연결

`brand_offerings`는 분석 확정 당시의 최대 5개 스냅샷으로 유지한다. 브랜드센터, DM, 콘텐츠에서 재사용하는 정식 데이터는 기존 원칙대로 `product_services`와 `product_service_versions`를 사용한다.

온보딩 확정 트랜잭션은 다음을 수행한다.

1. `brand_offerings`에 분석 스냅샷 최대 5개 저장
2. 같은 브랜드의 기존 제품·서비스를 정규화된 유형과 이름으로 비교
3. 동일 항목이 있으면 사용자가 수정한 기존 항목을 덮어쓰지 않음
4. 없는 항목만 승인된 제품·서비스 버전으로 추가
5. Wiki 재생성 요청을 한 번만 등록

따라서 온보딩이 생성한 대표 상품·서비스는 브랜드센터 `제품·서비스` 탭에 표시되고 DM 지식에도 포함된다. 재분석으로 전체 목록을 교체하지 않는다.

## FAQ 생성과 재분석 병합

온보딩 확정 시 워커가 제안한 FAQ를 `knowledge_entries`에 제안 초안으로 추가한다.

- 동일 브랜드의 정규화된 질문이 이미 있으면 기존 행을 유지한다.
- 사용자가 수정한 질문과 답변은 재분석이 덮어쓰지 않는다.
- 새로 발견된 질문만 새 초안으로 추가한다.
- 초안은 FAQ 탭에서 수정하고 활성화할 수 있다.
- 활성화된 FAQ만 자동응답의 직접 FAQ 판정과 Wiki 빌드에 포함된다.
- FAQ 탭의 기존 편집·활성화 동작은 유지한다.

별도 FAQ 테이블이나 새로운 등록 API는 만들지 않는다. 기존 `knowledge_entries`와 Wiki 갱신 흐름을 재사용한다.

## AI 자동응답 지식 화면

`AI 자동응답 지식`은 다음 확정 데이터를 읽어 보여주는 읽기 전용 화면이다.

- 승인된 브랜드 코어에서 만든 브랜드 정보
- 승인된 제품·서비스
- 활성화된 FAQ

이 화면에서는 다음 기능을 제공하지 않는다.

- 새 항목 등록
- 수정
- 삭제 또는 비활성화
- CSV 가져오기
- 수동 Wiki 재생성

FAQ 수정은 FAQ 탭, 제품·서비스 수정은 제품·서비스 탭, 브랜드 정보 수정은 브랜드 코어 탭에서만 수행한다. 자동응답 지식 화면은 실제 사용 데이터와 제외된 초안을 구분해 보여주되 원본 관리 화면으로 이동하는 링크만 제공한다.

## 호환성과 데이터 보존

- 기존 브랜드 코어, 제품·서비스, FAQ 데이터는 삭제하거나 자동 변환하지 않는다.
- 기존 `how_to`와 `guide` 지식 행은 DB에서 삭제하지 않지만 새 브랜드센터 탭에서는 직접 관리하지 않는다.
- `?tab=guide`와 `?tab=wiki` 기존 링크는 `AI 자동응답 지식`으로 연결한다.
- `?tab=how_to` 기존 링크는 FAQ 탭으로 연결한다.
- 회사명이 포함된 과거 분석 결과는 그대로 읽을 수 있다.
- 새 분석만 회사명 제안과 FAQ 제안을 포함한 확장된 v2 결과를 생성한다.

## 검증 범위

- 자료 등록 화면에 회사명 입력과 회사명 필수 검사가 없음
- URL 또는 문서가 없으면 분석 시작 불가
- URL·문서 근거에서 회사명 제안 생성 및 결과 확인 화면 표시
- 회사명을 찾지 못한 경우 빈 필드이며 최종 확인은 차단
- 대표 제품·서비스 최대 5개가 제품·서비스 탭과 Wiki 소스에 나타남
- 동일 제품·서비스가 재분석에서 중복 생성되지 않음
- 사용자가 수정한 제품·서비스는 재분석으로 덮어쓰지 않음
- FAQ 제안이 초안으로 생성됨
- 기존 FAQ는 보존되고 새로운 질문만 추가됨
- 활성 FAQ만 직접 FAQ 응답과 AI 자동응답 지식에 포함됨
- 탭 순서와 레거시 쿼리 매핑이 정확함
- AI 자동응답 지식 화면에는 쓰기 동작이 없음

## 배포 경계

API와 브랜드 인텔리전스 워커는 결과 계약을 함께 사용하므로 같은 릴리스로 배포한다. UI는 API가 확장 결과와 확정 데이터를 지원한 뒤 배포한다. 배포 검증은 이 변경에 직접 관련된 워커 계약 테스트, 브랜드 분석 저장 테스트, 브랜드센터 UI 테스트와 운영 스모크만 수행한다.
